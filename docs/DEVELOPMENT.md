# Спільна робота над EclipseCardReader

Цей документ пояснює, як двом розробникам клонувати проєкт, працювати кожному у своїй гілці та додавати готові зміни в основну гілку `main`.

У цьому репозиторії використовуйте:

- `main` — основна гілка зі спільною актуальною версією проєкту;
- `kostya_dev` — робоча гілка Кості;
- `qqeosas_dev` — робоча гілка другого розробника.

Не працюйте обоє в одній робочій гілці й не надсилайте незавершені зміни прямо в `main`.

## 1. Підготуй інструменти

Встанови:

- [Git for Windows](https://git-scm.com/download/win)
- [Visual Studio Code](https://code.visualstudio.com/)
- розширення **PlatformIO IDE** у VS Code

Оскільки репозиторій публічний, його можна клонувати без запрошення. Щоб відправляти гілки у цей репозиторій, власник має додати розробника до **Settings → Collaborators** з правом запису. Розробник має прийняти запрошення. Без цього він може працювати у власному форку, але не зможе пушити напряму в цей репозиторій.

## 2. Клонуй проєкт

Відкрий PowerShell або термінал VS Code та виконай:

```powershell
cd "$HOME\Documents"
git clone https://github.com/qqeOSAS/EclipseCardReader.git
cd EclipseCardReader
```

## 3. Перейди у свою робочу гілку

Кожен розробник переходить у власну гілку. Для Кості:

```powershell
git switch --track origin/kostya_dev
```

Для другого розробника:

```powershell
git switch --track origin/qqeosas_dev
```

Якщо Git повідомляє, що віддаленої гілки не знайдено, онови список гілок і повтори команду для своєї гілки:

```powershell
git fetch origin
```

Перевір, що перейшов у правильну гілку:

```text
git branch --show-current
```

Команда має показати `kostya_dev` або `qqeosas_dev` — залежно від того, хто працює.

Перший `git switch --track` створює локальну гілку, прив'язану до відповідної гілки GitHub. Надалі для оновлення та відправлення змін у ній використовуй `git pull` і `git push`.

## 4. Відкрий і збери проєкт

Відкрий папку `EclipseCardReader` у VS Code через **File → Open Folder…**. Вибирай корінь проєкту — папку, де знаходиться `platformio.ini`, а не `src`.

Дочекайся, поки PlatformIO встановить залежності, потім відкрий термінал VS Code і запусти:

```powershell
pio run
```

Якщо збірка завершується з `SUCCESS`, проєкт компілюється. Щоб прошити під'єднану плату, спочатку подивися її порт:

```powershell
pio device list
```

Потім заміни `COM3` на свій порт і виконай:

```powershell
pio run -t upload --upload-port COM3
```

## 5. Щоденна робота у своїй гілці

Перед роботою переконайся, що ти у своїй гілці, і завантаж її останні зміни:

```powershell
git branch --show-current
git pull
```

Після редагування перевір зміни, додай потрібні файли, створи коміт і відправ його:

```powershell
git status
git add src/main.cpp
git commit -m "Короткий опис змін"
git push
```

Заміни `src/main.cpp` у `git add` на шлях до файлу або файлів, які змінював. Переконайся через `git status`, що додаєш саме потрібні файли. Не додавай паролі, ключі Wi-Fi або інші секрети до комітів.

Кожен розробник пушить у свою гілку. Це дозволяє іншому бачити його коміти на GitHub, не змінюючи `main`:

```powershell
git push
```

## 6. Перенеси готову роботу в `main`

Коли зміни готові, на GitHub створи Pull Request зі своєї робочої гілки в `main`:

- **base**: `main`
- **compare**: `kostya_dev` або `qqeosas_dev` — власна робоча гілка автора змін.

Перегляньте зміни разом, потім злийте Pull Request у `main`. Не зливайте незавершену роботу; спершу перевірте, що проєкт компілюється командою `pio run`.

Після злиття підтягніть оновлений `main` у свою гілку:

```powershell
git fetch origin
git merge origin/main
git push
```

Якщо під час злиття Git повідомить про конфлікти, виправ їх у зазначених файлах, перевір результат, а потім виконай:

```powershell
git add шлях/до/виправленого-файлу
git commit
git push
```
